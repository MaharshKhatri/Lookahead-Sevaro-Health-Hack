# Requirements traceability: Sevaro Challenge 2 brief

Maps every requirement in `docs/brief_c2.md` to the code that implements it, the UI where a judge sees it, the tests that assert it, and a status. Built by reading the source and the tests (`describe`/`it` names are quoted verbatim); nothing here was inferred from docs alone. Policy choices behind each row are in `docs/OPEN_QUESTIONS.md` (OQ-nn) and `docs/DECISIONS.md` (D-nn).

Path prefixes: `E/` = `packages/engine/src`, `ET/` = `packages/engine/test`, `W/` = `apps/web/src`, `WT/` = `apps/web/test`, `E2E/` = `apps/web/e2e`. "Reference data at 18:20" means `data/raw` replayed at 18:20:00 ET (`snapshotAsOfMs`).

Status: **Covered** = implemented, visible in the UI (or engine-only by nature), and asserted by a test. **Partial** = implemented but missing a UI surface, an audit path, or a direct test. **Gap** = not implemented.

In-flight work: at the time of writing the working tree held uncommitted files from a parallel session (`packages/engine/src/forecast/*`, `packages/engine/src/util/rng.ts`, `packages/engine/test/forecast.test.ts`, `generalization.test.ts`, `injection.scenarios.test.ts`, plus exports in `E/index.ts` and constants in `E/policy.ts`). Rows that cite them say "(in flight)"; nothing in `apps/web` or in `detect`/`decide` reads them yet.

Totals: 85 rows: 77 Covered, 7 Partial, 1 Gap. Gaps and partials are listed with fixes at the end.
